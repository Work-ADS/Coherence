Accessibility

  • ariaLabel is required — icon-only buttons have no visible text, so the label is the only way screen readers announce the purpose.
  • When pressed is set, renders aria-pressed for toggle buttons.
  • When expanded is set, renders aria-expanded for disclosure triggers.
  • Focus ring uses var(--border-focus) and meets WCAG 2.2 focus-visible requirements.
  • Disabled state uses aria-disabled="true" and prevents click emission.
  • Always pair with afi-tooltip to provide a visible hint for sighted keyboard users.

Dos & Don'ts

Do

  • Always provide a descriptive ariaLabel (e.g. "Cerrar modal", not "X").
  • Wrap with afi-tooltip so hover reveals the action name.
  • Use ghost variant for chrome/toolbar contexts where buttons should be invisible until hovered.
  • Use outline variant when the button sits on a surface that needs visual boundary.

Don't

  • Don't use an icon button when a text label fits — prefer clarity over compactness.
  • Don't use identical icons for different actions in the same context.
  • Don't skip ariaLabel — the component requires it and will error.
  • Don't set custom sizes via CSS — use the size input for consistent hit areas.
