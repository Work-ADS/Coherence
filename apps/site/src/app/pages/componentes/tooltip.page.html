Components / Tooltip
  • Icon buttons — label for icon-only actions (notes, settings, back).
  • Keyboard shortcut hints — show Enter/Esc next to an inline-edit trigger.
  • Truncated text — reveal full content on hover when space is limited.
  • Disabled elements — explain why a control is unavailable.
Position
Shortcut

Accessibility

  • The tooltip popup has role="tooltip" and a unique id.
  • The trigger element receives aria-describedby pointing to the tooltip id — screen readers announce the tooltip content when the trigger is focused.
  • Tooltip dismisses on Escape key and on blur (via CSS :focus-within).
  • Respects prefers-reduced-motion — fade transition is disabled.
  • When disabled is true, the tooltip DOM is not rendered and aria-describedby is removed.

Dos & Don'ts

Do

  • Keep tooltip text short (1–2 words or a brief phrase).
  • Use shortcut input to show keyboard hints inline.
  • Set position to avoid overflow outside the viewport.
  • Use on icon-only buttons that lack visible labels.

Don't

  • Don't put interactive content inside a tooltip — use a popover instead.
  • Don't duplicate the visible label text in the tooltip.
  • Don't rely on tooltip as the only way to convey critical information.
  • Don't set delayMs to 0 — a small delay prevents accidental triggers.
