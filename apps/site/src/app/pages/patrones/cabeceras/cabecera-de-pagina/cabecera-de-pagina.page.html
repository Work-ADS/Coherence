Semantic Tokens

Decisiones

Decidido

Un componente, tres niveles

Consistencia cognitiva. Si cada página coloca el título, las acciones y las tabs en sitios distintos, el usuario paga un coste de aprendizaje por cada vista. Una plantilla común reduce ese coste a cero.

Un componente, no tres. El mismo <afi-page-header> con [level]="page | section | subsection" controla la escala tipográfica. Las variantes de densidad se controlan con [density].

Slots opcionales. Cada slot (actions, cards, filters, tabs) se enciende solo si se proyecta contenido. La cabecera nunca muestra filas vacías.

Decidido

Tabs — siempre el componente real

El slot [slot=tabs] recibe <afi-tabs> directamente. No es un mock ni un placeholder — es el componente de tabs que ya tenemos construido. Esto garantiza que los estilos, la accesibilidad y el keyboard navigation funcionan idéntico en todas las páginas.

Contadores opcionales. Cada tab puede incluir el número de elementos que contiene para anticipar el peso informativo antes del click.

Pendiente

Action bar — patrón propio

El action bar (chips de filtro + búsqueda + acción primaria) será un componente propio (afi-action-bar). Por ahora se proyecta como contenido libre en [slot=actions]. El patrón definirá la composición estándar: filtros a la izquierda, búsqueda y primary action a la derecha.

Pendiente

Data cards — patrón propio

Las métricas KPI (label + valor + trend) serán un componente propio (afi-data-card) que se proyecta en [slot=cards]. El patrón define el layout (grid row), el componente define la card individual.

Decidido

Contenido — bajo las tabs

El contenido de página vive debajo del header. El page-header define el "cromo" (contexto, navegación, acciones), y el contenido va en el flujo natural del documento — no dentro del componente header.

Tipos de contenido comunes: gráficos (evolución patrimonial, distribución), tablas (listados de activos, movimientos), o subsecciones que reusan el mismo page-header a un nivel inferior.
