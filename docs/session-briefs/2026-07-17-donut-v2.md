**Status:** ready to build (deliverable 3 of 4) · **Branch:** `feat/donut-v2`
**Sequence:** stat-tile → meter → **donut** (highest risk, built last while patterns are established). Build after meter-v2 clears its plan gate.

## Why this exists

The Overview's **Distribución de activos** tile uses `chart-bar` because there is no donut/pie primitive; a part-to-whole **donut** was the original design intent. This session builds it.

## Key architectural decision — read before building

Every existing chart in `libs/ui/src/chart/` (chart-bar, chart-line, heatmap, dumbbell…) is **shared / brand-neutral** — none carry `data-foundation` scoping. Richard's directive for THIS work is explicit: **v2 / foundations-modern only, not the old brand.** So this donut is built as a **v2 primitive** (`afi-donut-v2`, `[data-foundation="modern"]` scope, foundations-modern tokens), deliberately departing from the shared-chart pattern. 

**Lock this first thing with Richard:** confirm the donut lives as a scoped `donut-v2` rather than a shared `chart-donut` alongside the others. If he'd rather it join the shared chart family (brand-neutral, reusable by v1 too), that changes the location, token layer, and naming — do not assume. Recommend `donut-v2` per the stated directive, but surface the trade-off (a shared chart would be reusable everywhere; a v2-scoped one is consistent with the rest of this batch and the Overview).

## What this session produces

1. **`afi-donut-v2`** in `libs/ui/src/donut-v2/` — 3-file + `.variants.ts` + `index.ts`, exported from `@coherence/ui`. A part-to-whole donut: array of `{ label, value, ... }` segments, optional center total, legend. Reuse the shared chart infrastructure where brand-neutral and safe — `chart-a11y.ts`, `chart-legend.component.ts`, `chart-tooltip.component.ts`, `chart-format.ts`, `chart-data-table.component.ts` — rather than re-implementing legend/tooltip/a11y-table. Colors and surface come from foundations-modern tokens.
2. **A workbench section** — a few realistic allocations (2, 4, 6 segments), with and without center total, on the `data-foundation="modern"` root.

## Proposed API — lock after the architectural decision

```
segments   : { label: string; value: number; color?: string }[]  // color optional → auto-assign from data-viz palette in order
centerLabel: string   // optional big number in the hole ("100 %" or total) 
centerCaption: string // optional sub-label under it
showLegend : boolean  // reuse chart-legend
formatValue: (n) => string  // or reuse chart-format; segments show % of total
```
Open questions to lock (one at a time): (a) donut vs. pie (hole or no hole — donut per the name/intent); (b) does it show absolute values, percentages, or both in legend/tooltip; (c) sort segments by value or preserve input order; (d) max segment count before an "Otros" bucket.

## Tokens — token-guardian gate

Slice fills bind to the `--color-data-viz-*` categorical set (do NOT invent slice colors). Any new component token (e.g. donut stroke width, hole ratio if tokenized) routes through **ds-token-guardian**. No raw hex/px in `libs/ui/**`.

## a11y

Charts are the hardest a11y case — do not skip. Provide the accessible data-table fallback (`chart-data-table.component.ts` / `chart-a11y.ts` pattern) so the donut is not color-only. Each segment needs an accessible label with its value/percentage. Slice color must be paired with legend text; verify the categorical palette is distinguishable and check color-blind safety.

## Constraints

Responsive: donut scales within its tile; legend reflows. Motion on mount uses `--motion-*` tokens (respect `prefers-reduced-motion`). RAE copy. Pre-flight before handoff; tester verifies (including the a11y fallback).

## Out of scope

Multi-ring / nested donuts, interactive slice drill-down, the chart-line year-axis fix (own brief), the Overview recompose, doc page, dark-mode values.
