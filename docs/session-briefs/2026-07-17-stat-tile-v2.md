## Why this exists

The goal-driven client Overview (`apps/site/src/app/pages/demos/nueva-simulacion-overview/`, branch `feat/nueva-simulacion-overview`) renders its KPI bento tiles — Patrimonio neto, Tu dinero dura hasta, Año libre de deuda, Preparación jubilación — as `afi-card-v2` + hand-written label/value/delta markup. That inline composition is the thing being replaced. A reusable `stat-tile-v2` makes the KPI card a real primitive and keeps every future dashboard tile consistent.

Consumes ONLY `foundations-modern` tokens; renders correctly only inside a `[data-foundation="modern"]` scope. Parallel to any legacy KPI markup — do not touch v1.

This is the demo home — **not** a `/componentes` doc page (docs pages come later, with the site restructure).

## Proposed API — lock first thing

```
label        : string            // e.g. "Patrimonio neto"
value        : string            // pre-formatted display value ("1.240.500 €"). Tile does NOT format numbers — pass formatted text (mirrors card-v2's no-logic stance).
delta        : string            // optional, e.g. "+3,2 %". Empty → delta node omitted.
deltaTone    : 'positive' | 'negative' | 'neutral'   // drives delta color only; keep separate from `tone`
tone         : 'default' | ...   // OPEN: does the tile itself carry a tone/accent, or is it always neutral like card-v2? Default to neutral-only unless the Overview tiles show accented backgrounds.
caption      : string            // optional sub-label under the value ("hasta 2058"), if the Overview tiles use one
```
Decisions to lock before writing code (ask Richard one at a time, don't batch): (a) final tone axis — neutral-only vs. accented; (b) whether value formatting stays out of the primitive (recommended: yes, pass formatted string); (c) whether the delta needs a direction icon (▲/▼) or color-only, and if icon, sourced from where.

## Tokens

Expected to bind to existing tokens only (value = `--type-display-metric-*` + `--content-primary`; label = `--content-secondary`; delta = data-viz positive/negative). If a stat-tile-specific spacing token is genuinely needed (as `--pad-card` was for card-v2), add ONE, at the component-token layer, and route the diff through **ds-token-guardian** before commit. No raw hex/px in `libs/ui/**` (pre-commit hook blocks it).

## a11y

Non-semantic surface like card-v2 (no role/tabindex). Value and label read in visual order. Delta must not rely on color alone — pair the tone with a sign/word already in the `delta` text ("+3,2 %" / "−1,1 %") so screen readers and color-blind users get the direction. Confirm contrast of delta colors on the surface fill.

## Constraints

RAE copy for any demo labels (copy-skill.md); motion tokens only if animated; pre-flight (`docs/build-prompts/_pre-flight.md`) before handoff; tester verifies against this brief.

## Out of scope
