# A — Buttons + Forms audit (AFI default only, v2 + white-label ignored)

ZIP = .../scratchpad/zip (component CSS lives inline in each .jsx as a `CSS` template string; no separate .css).
OURS = libs/ui/src/<primitive>/. Tokens = libs/tokens/*.scss (checked, incl. responsive-token mixin usage).

## Cross-cutting findings (read first)

1. **Control-height scale differs, and Button/IconButton/Chip read a different scale in the zip.**
   - Zip has two scales. Field scale `--control-h-sm/md/lg` = 40/44/48 mobile -> 28/32/40 desktop (zip semantic.css:623-625, 804-806). Chrome scale `--control-size-sm..2xl` = 24/28/32/36/40 fixed (semantic.css:632-636), with `--icon-button-size-*` aliasing it (637-641).
   - Ours: `--control-h-sm/md` = 44/44 mobile -> 32/40 desktop, `--control-h-lg` 48 flat (libs/tokens/semantic.scss:642-650). Desktop sm/md/lg are 32/40/48 vs zip 28/32/40: every Input/Select/Search/Segmented is 4-8px taller than the zip. Mobile sm is 44 vs zip 40 ("size never inert").
   - `--control-size-*` and `--icon-button-size-2xl/xl` do not exist here. Our `--icon-button-size-sm/md/lg` = 32/40/48 (libs/tokens/components.scss:22-24, from --avatar-*), zip 24/28/32.
   - Button in ours (button.component.scss:134-151) reads `--control-h-*` (32/40/48 desktop) = a field-height button; zip Button md = 28 (reads `--control-size-md`). Decision needed: AFI traditional is adopting the zip dense chrome scale, so Button/IconButton/FilterChip move to `--control-size-*`; fields keep `--control-h-*` but with zip values.
2. **Zip component-scoped tokens missing from libs/tokens** (grep of every `var(--…)` in zip components/buttons+forms+FilterChip vs libs/tokens): `--button-primary-background-{default,hover,active}`, `--button-neutral-background-{hover,active}`, `--button-danger-background-{default,hover,active}`, `--button-danger-ghost-background-{hover,active}`, `--button-warning-ghost-{foreground,border,background-hover,background-active}`, `--checkbox-size-{md,sm,xs}`, `--checkbox-glyph-{md,sm,xs}`, `--control-label-font-{sm,lg}`, `--control-label-tracking`, `--control-size-{sm,md,lg,xl,2xl}`, `--icon-button-size-{xl,2xl}`, `--menu-item-{font,font-current,min-height,padding-block,padding-inline,gap}`. (Out of my family but surfaced: `--insight-trigger-*`, `--statuspill-warning-*`.) `--select-panel-max` is an optional override with a 320px fallback; `--seg-h/--seg-pad/--seg-r` and `--afi-reveal-x` are component-local custom props, not tokens. Primitives they point at (color-error-*, color-warning-*, azul-profundo-450, dimension-4-5/3-5/2-5) all exist in colors.scss/dimensions.scss. Our primary hover is `--brand-secondary-background-hover` = azul-profundo-600 (semantic.scss:178) vs zip 450.
3. **Our fields are "legacy"; zip fields use the `--input-*` token set and a shared field anatomy.** `--input-background/border/foreground/icon-*` exist in libs/tokens/semantic.scss:351-369 (ported) but no libs/ui primitive reads them (grep: zero uses in non-v2 scss). Input/Select/Search read `--control-background-default` + `--border-hairline` + `--radius-md` (8px); zip reads `--input-background-default` (white) + `--input-border-default/hover/focus` + `--radius-control` (10px). Labels: ours `--type-body-sm-500` primary ink; zip `--type-body-md-400` secondary ink. Ours puts a "*" with leading space; zip uses `margin-inline-start: 2px`. Focus: ours Input uses an inset ring, zip Input/Select use outer `0 0 0 2px --border-focus` (Search is inset).
4. **Zip fields all share: `help` (ⓘ via Tooltip + IconButton quiet sm), `required`, `hint/error`, `shape: rect|pill`, `unit`, `numeric`, forwarded `id`/`aria-describedby` merge, and field anatomy (fieldset/legend for groups).** Ours has none of `help`, `shape=pill`, `numeric`, `unit` (has prefix/suffix instead). `help` needs IconButton `quiet` variant (missing) + Tooltip + an info icon.
5. **Focus ring token is undefined here.** `icon-button.component.scss:27` and `inline-edit.component.scss` use `var(--focus-ring)`; no definition anywhere in libs/tokens or libs/ui (grep). IconButton therefore has no visible keyboard focus ring today. Zip uses the literal `0 0 0 var(--border-width-thick) var(--border-focus)` and publishes `.afi-focus-ring` (zip styles.css:30-33; tests/focus-ring-tests.html asserts exact ring, no ring on mouse focus, >=3:1 vs surface-default and surface-subtle in light+dark). Cheap fix, high value.
6. **Hard-coded z-index / hex-free but non-token motion.** Select panel z 50 / backdrop 40 (select.scss), Search suggestions z 50, FilterChip menu z 50, DropdownPanel z 50: zip uses `--z-floating` (1050, exists at semantic.scss:440) + portal to body + fixed coords. Checkbox/Radio use inline Tailwind + literal ms/cubic-bezier + `stroke="white"` (checkbox.component.ts:73,85; radio uses `bg-white`), i.e. not token-clean and not 3-file (inline template+styles; project rule bans it).
7. **Hit-target philosophy differs.** Ours: checkbox wrapper min 44x44, switch min-height 44 (switch.scss:19). Zip: box is exactly 18/16/14 border-box, hit area = the label (+ a 3px/2px `::after` extension), container owns target size; radio/seg get 44px rows only below 640px viewport (tools/checkbox-sizing-tests.html, Radio.jsx @media).

Deps NOT yet created: `--control-size-*`, `--control-label-font-sm/lg`, `--control-label-tracking`, all `--button-primary/neutral/danger/danger-ghost/warning-ghost-*` (list in finding 2).

Ours is composed: `afi-radio-group` (`value, legend, required, disabled, ariaLabel, ariaLabelledBy, orientation horizontal|vertical`, `valueChange`) + `afi-radio-group-item` (`value, label, hint, disabled, size sm|md, compact, name, selected`, `selectedChange`). The parent does NOT push `name`/`selected` to items (ts constructor comment: "serves as the semantic container"), so consumers must wire `[name]`/`[selected]` on every item by hand - arrow-key grouping depends on shared `name`. Missing: `options` array API, `label` (ours `legend`) + `hint` + `error` on the group (no field anatomy, no `aria-invalid`/`aria-describedby` on group), `row` vs `orientation` (default differs: ours horizontal, zip vertical column; zip row stacks below 640 container), `description` (ours `hint` per item). Ours `size sm|md` and `compact` have no zip equivalent (zip ring is always 18px).
- **Look gap:** ring 20/16 (`h-5/h-4`) -> `--checkbox-size-md` 18 with `--border-width-thick` + `--input-border-default`, hover `--input-border-hover`; selected: ours fills ring with `bg-action` and a WHITE dot (`bg-white`); zip ring stays `--input-background-default` with border + 10px dot (`--dimension-2-5`) in `--brand-secondary-background-default` (outline style, not filled). Motion: ours spring `250ms cubic-bezier(.34,1.56,.64,1)` + press scale .9, raw values; zip dot `scale(0)->1` with `--duration-fast/--easing-enter`. Legend: ours `text-body-sm font-medium` primary ink (zip: "never semibold", `--type-body-md-400` secondary, `margin 0 0 --space-2xs`, asterisk `margin-inline-start:2px`; ours inline `style="color:…"`). Gaps: zip group `--space-sm` col / `--space-lg` row.
- **Behaviour/a11y:** zip wrapper is `<fieldset><legend>` with `aria-labelledby/-required/-invalid/-describedby` on the `role=radiogroup`; `@container (max-width:640px)` stacks row groups; `@media (max-width:640px)` turns each option into a 44px full-row target with group gap 0 (label is the target). Ours: `<fieldset role="radiogroup">` (role on fieldset, legend present), `aria-label/-labelledby` passthrough, dev warning if no name. Native radios give arrow-key nav only if names match. No reveal hook (zip: `FieldReveal inset={9}` under a radio group). Tests: Radio has no dedicated tools page; covered by tools/segmentedcontrol-field-tests.html ("canonical styling vs Input and RadioGroup", 4px label->control and control->message gaps) and tools/field-help-tests.html.
- **Verdict:** **structural (L).** Rewrite to 3-file + options API + field anatomy (or keep the item-composed API but have the parent own `name/selected`). Deps NOT created: `--checkbox-size-md`.

### switch -> Switch (+ FieldReveal unmatched)
- **API gap:** zip: `label, checked/defaultChecked, disabled, size sm|md, onChange(e), id, help, helpLabel, children` (children = fields it opens, rendered through FieldReveal, `aria-expanded/-controls`). Ours: `checked, size, label, hint, disabled, ariaLabel` + `checkedChange`. Missing: `help`/`helpLabel`, `children` reveal (content projection slot + FieldReveal primitive), `defaultChecked`. Ours-only: `hint` (second line under label).
- **Look gap:** track md 40x24 (ours dimension-10 x dimension-6, same), sm 32x18 (ours 32x20 `dimension-8 x dimension-5`). Thumb md 18 at 3px inset (ours 20 at 2px `--space-3xs`), sm 13 at 2.5px (ours 16). Travel 16/14 vs ours 16/12. Off colour: zip `--control-background-active`; ours `--color-afi-control-300` PRIMITIVE colour (token-rule smell), hover control-400. On colour: zip `--brand-secondary-background-default`; ours `--color-afi-azul-profundo-700`/800 primitives (hard brand colour, wrong role + would ignore dark mode). Thumb: zip `--color-base-white` + `--elevation-sm`; ours `--surface-default`. Gap switch->label: zip `--space-sm`; ours `--space-xs`. Motion: zip track fades `--duration-base --easing-standard`, thumb travel `--duration-base cubic-bezier(.34,1.56,.64,1)` with overshoot + press-stretch (width 18->21 while :active; sm-sized reduced-motion reset); ours `--duration-fast` plain ease, no overshoot/stretch. Disabled: zip opacity .55, ours .5. Min-height: ours `min-height --dimension-11` (44); zip none (target = label row).
- **Behaviour/a11y:** zip: `<label><input type=checkbox role=switch>` (native, Space toggles free, label click toggles); help ⓘ sits inside the label but cancels activation so it never toggles; switch named from label text span only when help is present. Ours: `<label><button role=switch aria-checked>` with extra `keydown.space` handler that `preventDefault`s then calls toggle (note: a click on label then also fires the button click - fine; double-fire risk with Space+keyup click is prevented by preventDefault). Ours has no `aria-labelledby` to the label (relies on label wrapping a button, which names it implicitly). Tests: tools/switch-reveal-tests.html (no children = plain switch; off removes fields + `aria-expanded=false`; on shows + true; `aria-controls` -> region; guide centred on track centre +/-0.5px for md and sm; dashed `--border-default` hairline; starts `--space-xs` below the switch; fields `--space-md` right of guide; nested = one guide, no re-indent; conditional field stays under same guide; help `--space-2xs` after label, switch named by label text only, pressing help never toggles).
- **Verdict:** **API gap (M).** Look = restyle (switch.scss token swaps + sizes); `help` + reveal `children` + FieldReveal are new. Size M. Deps NOT created: none strictly (all tokens exist: `--control-background-active`, `--color-base-white`, `--elevation-sm`); recommend `--switch-*` only if sizes go token-ised. Unmatched dependency: FieldReveal.

### segmented-control -> SegmentedControl

Ours: `options ({value,label,disabled}), value (model, two-way, required), size, ariaLabel`. Missing: `appearance=solid`, option slots `icon`/icon-only (square seg + ariaLabel)/`count`/`dot`/`meta`, `fullWidth` (default true in field mode; ours inline, `flex-wrap` allowed), whole-control `disabled`, `defaultValue` (uncontrolled; ours `value` is `model.required`), field anatomy (`label/hint/error/required/help` -> `<fieldset><legend>`, error ring on track, "(obligatorio)" sr text), `string[]` shorthand. Ours-only: `[data-brand=unicaja]` radio-card block = white-label, leave frozen.
- **Look gap:** track radius zip `calc(--radius-control + --seg-pad)` (concentric, 12), padding `--space-3xs` (2px) gap 2px; ours `--radius-lg`, padding `--space-2xs` (4px). Track height = `--control-h-sm/md/lg` (matches Input/Select at same size, "same height" tests); ours has no track height, segments are hard `--dimension-7/9/10` (28/36/40) + 4px padding = 36/44/48 outer, so it does not equal an Input. Thumb: zip `--surface-raised` + `--elevation-sm` + inset 1px hairline, radius `seg-r - seg-pad`, slides `transform+width --duration-base --easing-enter`, inset clamped to the inner box, measured per button (handles unequal widths), re-measured on ResizeObserver + `document.fonts.ready`, `nothumb` fallback + `--idle` (no transition on first paint); ours thumb = `--control-background-active` + `--elevation-sm`, transform only w/ `--duration-base --easing-standard`, width/height `--duration-fast`, double-rAF measure, no clamp/font-load measure (initial 0x0 until effect). Type: zip ONE weight (500) in all states, ink changes only (secondary -> primary), labels never change width; ours switches 400 -> 500 on active (width jitter), tertiary ink. Segment padding `--space-md` / sm `--space-sm`; hover ink primary. Focus ring: zip INSET on the segment (never clipped); ours outer `0 0 0 2px` (clipped by parents).
- **Behaviour/a11y:** zip radiogroup + roving tabindex (checked is the one tab stop), Arrow keys move AND select with wrap, Home/End jump, skips disabled, icon-only warns without ariaLabel, `title` on truncated labels. Ours: `role=radiogroup` + `role=radio` + `aria-checked` but every button is a tab stop (no roving tabindex), no arrow/Home/End handling -> ARIA pattern incomplete. Tests: tools/segmentedcontrol-tests.html (row of Input/Select/Segmented same height; thumb inset >= track padding and thumb == active segment at x/width +/-0.6px incl. LAST option selected; equal left/right text padding >= 11.5px), tools/segmentedcontrol-field-tests.html (bare DOM unchanged; with anatomy: fieldset+legend names radiogroup, canonical label style = Input/RadioGroup, 4px gaps, required asterisk aria-hidden + sr "(obligatorio)", `aria-invalid`+error ink+1px error ring same width, error never hidden by component, controlled/uncontrolled, whole-control disabled keeps selection visible and emits nothing, per-option disabled, roving tabindex, arrow/End/Enter/Space, dark theme, no console warnings), tools/control-height-floating-tests.html.
- **Verdict:** **API gap (L).** New inputs (`appearance`, option slots, `fullWidth`, `disabled`, `defaultValue`, field props) + keyboard rewrite + measured-thumb rewrite. Size L. Deps NOT created: none (`--surface-raised`, `--control-background-default/-disabled`, `--disabled-foreground` exist); `--seg-*` local props.

### filter-chip -> FilterChip (toggle mode) + MultiSelect-with-chip-trigger (dropdown mode)
- **API gap (toggle):** zip: `label, icon, selected, disabled, value, onToggle, onRemove, onClear, removable, asTrigger, expanded, onReset, ariaLabel, size sm|md, appearance default|outline, onClick/onKeyDown/aria-expanded/-haspopup/-controls` passthrough to body. Ours toggle: `label, size sm|md, disabled, ariaLabel, mode, selected, count, dismissable` + `selectedChange, dismissed`, icon via `slot=iconStart`. Missing: `value` (applied-value segment: separator + brand-ink value + clear x, truncating with ellipsis + conditional `title`), `appearance=outline` (dashed when idle, solid when applied, transparent fill), `asTrigger/expanded/onReset` (menu-trigger mode, leading reset, trailing rotating caret; this is what `Select`/`Menu` clone as `trigger`), `onClear` vs `onRemove` split. Renamed/different: ours `dismissable` ~ zip `removable`, `count` badge has no zip equivalent (zip uses `value`). Dropdown mode: ours `mode="dropdown"` embeds a multi-select panel (`options, selectedValues(Set), showSelectAll, selectAllLabel, dropdownAriaLabel, selectionLabel`) - in the zip that is `MultiSelect` + `FilterChip asTrigger`; no zip equivalent for chip-owns-panel. Zip sizes: sm 24, md 32 (`--control-size-lg`), outline md 28 (`--control-size-md`); ours sm `--dimension-6` (24) / md `--dimension-8` (32): same pixels, wrong token source.
- **Look gap:** zip bg `--control-background-default` w/ hover `--control-background-hover`, active `-active`, border `--control-border-default/-hover`; selected fill `--control-background-selected`, border `--control-border-selected` (holds through hover/press, only fill responds). md inactive uses input surface/border (`--input-background-default`, `--input-border-default`) and `--input-foreground-placeholder` name. Ours: `--surface-base` / hover `--surface-subtle` / border `--border-hairline`; selected = FULL brand fill `--brand-primary-background-default` + white text (toggle) or `--surface-selected` tint (dropdown): the zip selected state is a quiet tint with an applied-value in brand ink, never a solid brand pill. Type: zip body-sm-500 (sm) / body-md-400 name + 500 value (md); ours `font-weight:500` on label over body-sm-400 on both sizes. Caret 12px (sm) / icon-sm (md); ours dimension-3. - **Behaviour/a11y:** zip anatomy: pill is a wrapper `<span>` around two sibling buttons (body, x) - "a button cannot contain a button"; body `aria-pressed` (toggle) or `aria-haspopup/-expanded` (trigger), x buttons named by verb + label ("Quitar filtro de X", "Borrar X"), body keyboard focus draws a 2px outline on the pill (`afi-chip--focus`, instant), x draws its own ring, disabled hides every x, hover/active drive fill from the pill so hovering the x lights the whole shape, no scale/blur motion ever, width snaps.
