# Audit B: display + feedback primitives (AFI default only, *-v2 and white-label ignored)

Paths: ours = libs/ui/src/<p>/ ; zip = $ZIP/components/{display,feedback}/ ; tests = $ZIP/tools/.
Method: every `var(--x)` in the zip .jsx for these components was checked against libs/tokens (incl. responsive-token mixin). RESULT: every shared zip token these components use already exists in libs/tokens. Only component-local custom props (--afi-ps-gap, --drawer-*, --afi-group-bleed-*) are zip-internal. The zip-scoped `--insight-*` (28), `--statuspill-*` (20), `--tour-*` (11) do NOT exist anywhere in libs/tokens, but they belong to unmatched components (below), not to this family.

## Cross-cutting findings
1. **Section / page-header(level=section) / PageSection is a three-way overlap.** Zip has two components: PageHeader (page title only, no levels) and PageSection (level section|subsection, appearance plain|framed, description, actions, actionsPlacement). Ours: `afi-section` (boxed, collapsible) and `afi-page-header` (levels page|section|subsection + sticky chrome + slots + collapsible). `--section-radius` (16px) has ONE consumer, `afi-section` (section.component.scss:13); the zip consumes it nowhere (only in _ds_manifest/_adherence lint lists). `--radius-section` (12px) is what the zip uses for framed PageSection, Card bordered, MetricCard, DataSection, DatePicker; ours has ZERO consumers in libs/ui (page-header.component.scss:~75 hard-codes `--radius-lg`, same 12px value, wrong token). afi-section is used by 17 files, nearly all blog/iteracion-N versioned snapshots; live pages use page-header level=section (5 files; 49 page-header files total).
2. **Overlay family is legacy.** modal/drawer/toast/tooltip/loading-overlay predate the zip's overlay rules: no blur on scrims (`--overlay-blur` / `--overlay-blanket-drawer` exist in libs/tokens but have zero consumers in libs/ui), no initialFocusRef/returnFocusRef, no "Escape already consumed (defaultPrevented)" protocol between Tooltip/Select and Modal/Drawer, no z-index ladder (zip: Drawer 900/901, Modal 1000, `--z-floating` 1050, Tooltip 1100, ProgressOverlay 1200; ours: tooltip 60, drawer 50, toast 70, loading 10, page-header 10, all raw). Tooltip is not portalled (zip portals to body so tooltips never add scrollWidth in `.afi-table-wrap`).
3. **Our components reference tokens that do not exist (silently invalid in AFI default):** `--duration-normal` (toast.scss animation shorthand becomes invalid, so toast enter animation never runs), `--elevation-2` (toast shadow; defined only under foundations-modern), `--type-body-sm` (toast message font; status-chip.variants tokenUsage), `--focus-ring` (status-chip.scss:~38 so the focus ring is dropped), `--space-3` (page-header borderless padding/margin), `--font-family-display`, `--radius-xs` (logo anchor radius), `--border-base`/`--border-thin` (download-md-button), `--toast-action-color`/`--toast-hover-bg` (have fallbacks, no token), `--dimension-modal-sm..xxl` (fallbacks only; no token defined), `--font-mono` (kbd; only defined in one demo page scss). Badge/Drawer/StatusChip(variants) are Tailwind-class implementations riding the tailwind.config.js legacy colour aliases (neutral-*, action-*, system-*, surface-base): `neutral-200`/`neutral-800` map to raw `--color-afi-control-*` ramp steps, which do not flip in dark mode.
4. **Zip's `--surface-context` contract is unimplemented.** Zip Card, Modal, framed PageSection redeclare `--surface-context` so flush Table headers paint the container's surface. Token exists (semantic.scss:80) but no libs/ui component redeclares it.
5. **Slot discipline vs zip role props.** Zip PageHeader fills Button variants by role (`backAction` ghost, `secondaryActions` secondary, `primaryAction` primary); ours has `[slot=actions|primaryAction]` only and warns at >3 actions. No PageActions equivalent exists anywhere in libs/ui.
