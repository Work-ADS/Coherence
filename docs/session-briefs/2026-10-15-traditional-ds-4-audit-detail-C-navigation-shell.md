## Biggest cross-cutting findings
1. Two missing token families block every restyle here: `--sidebar-*` (about 28, zip semantic.css:353-384) and `--menu-item-*` (6, :342-347), plus `--button-primary-background-default`. `--nav-item-*` already match zip exactly, so nav-item/nav-section/menu hover states are pure SCSS swaps once these exist. Create them in `libs/tokens/semantic.scss` (guardian review) before touching Menu/Sidebar/Stepper.
2. Bars and shells are different products: our `top-bar` is a generic 56px slot shell, zip TopBar is a 48px data-driven Wealth Planner bar (trail, state menu, indicators, rename, ≤768 hand-off), and our `shell` has no bar slot, content card, drawer or overlays slot. Chunk 7 (swapping `site-planner-top-bar` / `site-planner-sidebar`) needs a DS planner-shell composite plus the sidebar variants (`flush-light` / `inset-dark`, 72px rail, data-driven items); ours hover-expand/pin modes have no zip counterpart (decision needed).
3. Zip encodes a11y/behaviour contracts we fail: Stepper (list/listitem `aria-current`, hidden «completado/pendiente», buttons only for done + `onStepClick`; `stepper-a11y-regression`), Tabs (`both` fill-mode leaves transform/filter that traps fixed popovers, first render animates, no resize/font indicator refresh), Menu (Escape must not close a parent Drawer, no focus return, no checkbox/`aria-checked` rows, hard-coded z-index vs `--z-dropdown`), Sidebar (invalid `aria-expanded` on `nav`, `role=list` without listitems, section geometry per `sidebar-section-geometry-tests`: chevron 4px after label in 20px box, surface inset 4px, 36px rows, label x = child icon x), plus collapsed `nav-section` children staying focusable.
